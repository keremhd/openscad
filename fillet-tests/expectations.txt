# The two pocket cases used to segfault here, and it was not a fillet bug: the
# pocket's apex sat exactly in the plane of the block's top face, so the model
# pinched to a point at that vertex, and CGAL's convex decomposition — which
# every dilation goes through — dies on such a vertex. Reproducible in eight
# lines with no fillet node present, and unrelated to the pocket's face count:
#
#   minkowski() {
#     difference() {
#       translate([-30,-30,0]) cube([60,60,60]);
#       cylinder(r1 = 30, r2 = 0, h = 60, $fn = 3);   // apex at z = 60
#     }
#     cube(12, center = true);
#   }
#
# Move the apex a millimetre either way and it is clean, so the cases now leave
# material above it (CAP) and the crash is gone for good.
#
# What is left is not about the fillet either. Corner cells exist now and these
# pockets close correctly — pinned exactly, against a shrink-and-grow reference,
# in FilletCompare_test.cc. But at every corner a sphere sits tangent to three
# walls, and the surfaces meeting along those tangencies leave triangles too
# small to survive CGAL quantising its input, so the applied result is still not
# a solid the Nef kernel will dilate. Reducing that tangential contact is what
# turns these green; nothing about the corner geometry will.
case_junction3_pocket   *  sandwich  FAIL
case_junction4_pocket   *  sandwich  FAIL

# These two are red because "sandwich" cannot pass on a sharp apex, not because
# the apex is wrong. The check asks that the result stay within the tool's own
# size of the model, and rounding a point moves the surface by far more than the
# radius: a ball of 6 seated in a 30 x 60 cone tops out 18.7 below the tip, so
# the correct answer is three radii from the model. That is the coarseness a
# reference-free check is documented to have. The exact comparison lives in
# FilletCompare_test.cc, where both apexes are checked against the true rounded
# solid; here the contour stack is what to look at, and a section below the
# corner comes out a circle because it is the corner ball cut by a plane.
case_junction3_apex     small  sandwich  FAIL
case_junction4_apex     small  sandwich  FAIL

# The needle used to sit here twice over: its beads stopped eighty radii below
# the apex, and dilating a 3 x 120 spike through CGAL took longer than any bound
# worth setting, so the check never returned a verdict. Both are gone. The size
# gate refuses the three slant creases — the spike is thinner than the tool for
# its last 27 mm — so only the base beads are built, the tip is left alone, and
# what the check has to dilate is small enough to finish. The runout fallback

# The equal-radius tee is the pocket cases' failure a third time, and the one
# place it can be shown to be the kernel rather than the geometry. Where the two
# seam ellipses cross, the cylinders share a tangent plane, and four spines run
# out onto that tangency; the triangles that leaves are too small to survive CGAL
# quantising its input, so the dilation "sandwich" needs cannot be taken.
#
# The applied result itself is fine, and identical either way round: with the
# branch along X and with it along Y the operator reports the same 852 edges and
# the same 80 selected creases, and both results come back NoError, genus 0. Only
# the dilation differs, because rotating the branch moves where the near-tangent
# slivers land relative to the quantising grid. A check that one orientation
# passes and its mirror image fails is measuring the kernel, not the solid. The
# case keeps the orientation whose picture is legible.
case_pipe_tee_equal     small  sandwich  FAIL
