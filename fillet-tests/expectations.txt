#   <case>  <variant>  <check>  PASS|FAIL|CRASH|TIMEOUT|ERROR

# "*" matches anything; the FIRST matching line wins, so put specific cases
# above the catch-alls. Anything not listed is expected to PASS.
#
# This file is a ledger of TEMPORARY DEBT — what is red today and expected to go
# green as the operator is built. It is not where the suite records what correct
# behaviour is; that lives in the case files, as each variant's kind. The
# distinction matters when deleting lines: a line here means "not there yet", so
# a permanent contract must never be written as one, or someone will eventually
# delete it believing they fixed something.
#
# The rounded tools are red on purpose: the operator builds the wedge but not
# the rolling ball, so fillet_tool/round_tool still emit nothing. That means
# `emits` fails, `tool` fails (the residual is the whole reference), and
# `sandwich` passes trivially because the applied result is just the model. When
# a milestone lands, the lines it turns green are what you delete from here.
#
# chamfer_tool and bevel_tool need only the wedge and are green on every check
# except `drops`. They are listed as PASS rather than left out only because they
# have to outrank the catch-alls; anything genuinely unlisted is expected to pass
# too.
