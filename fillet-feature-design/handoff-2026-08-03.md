## Standards the owner set — apply to every decision

1. **A defect is real only if refining `$fn` does not fix it.** Patchiness that shrinks
   with refinement is faceting and is acceptable.
2. **Practical and visual, not mathematically pure.**
3. **A visible line where two roundings meet is fine.** The bar is a *valid solid*, not
   a smooth corner.
4. **Generalisation over patchwork.** Bad but uniform beats excellent but discontinuous.
5. **Do not reverse-engineer curvature from the tessellation.** (D19's recognition stays
   on the right side of this by fitting the model's own *facet planes*, never inferring
   from facet angles.)
6. **Judge by maintenance cost, not development effort.**
7. **No user option for wall fitting** — decided. `plane + cylinder`, always on.
8. **The unit tests are not final.** "Written to make code pass." A test pinning current
   behaviour is not a constraint if the behaviour is wrong. But do not edit a pin to make
   a change pass — derive it from a hand-built ideal and say how.
9. **The design log files are dev artifacts** and will be deleted before merge.
10. **A valid solid with an unfilleted crease beats a shattered one.** A false refusal is
    the safe error; a false acceptance is the dangerous one.

## READ THIS FIRST — traps that have each cost hours

1. **Builds are silently discarded in this environment, and `make` reports "Built target"
   for binaries that do not exist.** ALWAYS verify the binary's mtime is newer than your
   last source edit before trusting any measurement. This invalidated one agent's entire
   report and cost another two full rounds. If builds misbehave, retry with
   `dangerouslyDisableSandbox`.
2. **`env $VAR ...` in zsh performs no word splitting**, so a second probe is silently
   dropped. Cost one agent a full round of measurements.
3. **This machine's locale uses comma decimals** — `atof`/`strtod` on `"0.1"` silently
   yields 0, and `printf`-family diagnostics mangle parsing. Use `istringstream` /
   `ostringstream` imbued with `std::locale::classic()`.
4. **The crease threshold is `1.5 × max($fa, 360/$fn)`, and `$fa` defaults to 12.** A model
   that sets only `$fn` is measured through an **18° threshold that cannot see its own
   tessellation**, however fine `$fn` is. Set `$fa = 360/$fn; $fs = 0.01;` in every model
   and confirm the threshold moved (5.6° at `$fn`=96). This voided an entire round of D20.
5. **A radius that does not fit is warned about, skipped, and still exports a plausible
   mesh.** An export succeeding proves nothing — read the warnings.
6. **Derive genus from the mesh, not from the ECHO output.** `>2`-face edge counts are
   weld-tolerance sensitive (205 at weld 1e-5 vs 0 at 1e-6 on the same mesh) — state your
   tolerance and read for direction and zero only.
7. **`$fn` sweeps must use a tessellated model.** `pocket.scad` and `rhomb.scad` are
   entirely planar, so sweeping `$fn` over them tests nothing. One report's whole `$fn`
   series was vacuous for this reason.
8. **Brushes are children 1+, not a `brush =` argument** (that is a parse error):
   ```openscad
   difference() { thing(); round_tool(r = 2) { thing(); brush_shape(); } }
   union()      { thing(); fillet_tool(r = 2) { thing(); brush_shape(); } }
   ```
9. **Long silent commands trip a 10-minute stall watchdog — it killed eight runs this
   session.** Usual culprits: a first full build in a fresh worktree, and an unbatched
   sweep. Run bounded batches that stream output, checkpoint every row to a file, and
   **commit as you go**. Agents were also cut by host power loss; every one resumed
   cleanly from its transcript, but **only committed work survived**.
10. **On a rotated bore, Manifold and CGAL do not evaluate the same target**
    (`hp_fn96_rot0.5` is 848 v / 1704 t under Manifold, 1104 v / 2216 t under CGAL). Cross-
    backend verdicts there are about two different solids. Phase tables must be one backend.
11. **Resource limits**: `cone_fn192` under CGAL peaks at **156 GB and OOMs in every
    binary**, including clean base. `cone_fn384` and `sph_across_fn384` cannot be exported
    at all on this machine.
12. Tooling: plain `python3` only — no matplotlib, PIL, cairosvg, rsvg-convert. ImageMagick
    exists but its SVG rasteriser has no font (`-font /System/Library/Fonts/Helvetica.ttc`).

### Nondeterminism is MUCH wider than this record assumed — and it contaminated byte-identity

Long recorded as two isolated cases:

- `rounded_cube` at `$fn` 192: three different md5s over three runs in **every** binary
  including clean HEAD; same 24156 tris, volume equal to 13 digits. (Also seen at `$fn` 96.)
- hole-in-a-flat-plate: identical volume 14857.3025669748, differing vertex order.

**Integration found it reaches far further.** `box_cube_fn96_r1`, `box_cross_fn96_r1` and
`box_L_fn96_r1` each give **three different md5s from three runs of one binary with identical
environment**. These are ordinary box models in the middle of the 144-run census.

**Consequence for the whole effort**: `cmp` byte-identity against a clean build was the primary
control almost everywhere in this work, and figures like "128 of 144 census byte-identical" were
partly measuring **run-to-run variation, not differences between builds**.

**Read the direction of the error carefully before over-correcting:**
- A reported **"byte-identical"** remains strong evidence — identity *despite* possible
  nondeterminism cannot be a false positive.
- A reported **"differs"** may be noise rather than the change under test. Several agents already
  caught this in-flight and re-ran before reporting a vertex-order difference as a regression; that
  instinct was correct and should be standard.
- **Verdicts that rest on genus and component counts are unaffected** — those were stable across
  every repeat.

**Standing rule from here**: establish the nondeterministic set for your corpus first, by running one
binary over it two or three times, then state byte-identity as *"identical outside the
nondeterministic set"* — or fall back to volume, which is stable to 13 digits.

## The design

A vertex is a **seam vertex** if some *model crease* leaving it (dihedral passing
`isFeatureAngle` at the selection threshold) is NOT in the filleted set. The owner's
principle: *does an original crease leave the vertex still sharp? If so, the two beads must
meet in a **seam that lines up with that edge** — a ball can never line up with a sharp edge,
it rounds across it. If nothing sharp leaves, a corner ball is correct.* Why the crease went
unfilleted — brush, size gate, feature-angle filter — does not matter.

**Four interacting mechanisms**, each added to stop the previous one misfiring:

1. **Local grouping** — seam vertices build no ball, so their chains stay unlinked in the
   union-find and take **per-chain** canal subtraction; elsewhere global, as before.
2. **The seam overrun** — `seamOver` = 0.10·r, extrapolating the end section past the vertex
   so beads cross transversally instead of grazing. `seamRoom` bounds it by available
   material; a **retreat fallback** stands the bead back where there is none.
3. **`arrivesStraight`** — apply the rule only where every bead reaches the vertex running
   straight (last two segments collinear to 1e-9); a one-segment crease passes.
4. **`anyServed`** — if no vertex carrying ≥2 chain ends is actually served, the union-find
   takes the pre-feature branch and everything lands in group 0, subtracting globally
   **exactly as HEAD does**.

## The mechanism behind the last blocker

The overrun continues the bead along the line its last segment lies on. On a tessellated arc
that segment is a **chord**, and a chord produced past its end **leaves the circle on the
outside** — so the extrapolation lays the bead a hair outside the wall and tangency becomes a
sliver resting on it, which is the very degeneracy the overrun exists to remove. Measured:
radius 7.996745 → 8.002908 on an r=8 cylinder, sagitta 0.006168. `seamRoom` cannot see it by
design (it ignores faces the run is parallel to).

# D19 — the subtractive scalloped ledge

**Status: route found and working; one bar unmet; a standoff attempt was in flight at the end
of the session.** Env-gated probes (`SEAT`, `WALLFACE`), default **off**.

## The defect

`round_tool` on a **curved wall** stops short and leaves un-cut original surface standing as a
ragged ledge. No bump; an under-cut. Worst **1.526 mm = 0.76 r** at Ra=10, Rb=5, r=2, `$fn`=96.
It **plateaus rather than converging** — 1.7934 / 1.6331 / 1.5261 / 1.4665 / 1.4347 at `$fn`
24/48/96/192/384, floor ≈1.40 mm — while the flat control converges as 1/`$fn`².

## Three findings that took three agents

1. **Facet seating alone makes it worse**: 1.5261 → **2.9869**, genus 0 → 16. Two independent
   implementations (a 70-line solver and the shelved 790-line recogniser) agree to four
   decimals, so **the convex regression is the seating, not any recogniser** — that retires a
   790-line suspect.
2. **A multi-vertex wall face alone does nothing**: 1.5261 → 1.5261. On HEAD's unseated
   placement the tangency point already stands off the wall, so the chord already clears the
   bulge. HEAD's ledge is not the chord — it is the setback `r·tan(φ/2)`, reaching 40 % of the
   band.
3. **Together, with the wall *recognised*, they work.**

## The recognition — 101 lines, not 790

A wall is read as the set of **facet planes** its triangles lie in, **never as a set of
points**: one plane → it is a plane and the ball is not moved; three or more distinct planes
whose normals are all square to one axis and all tangent to one cylinder about it to
1e-9·scale → it is that cylinder; anything else → unrecognised, nothing moves.

**Fitting planes rather than vertices is what makes it work**: a boolean drops new vertices on
the *flat* of a facet, so a wall's vertices lie on no cylinder even when the wall is one, while
its facet planes still do. Nothing is inferred from a facet angle — the cylinder recovered is
the one the model's own faces are tangent to (9.99465 = 10·cos(π/96) on the D19 shape). Whole
diff +162/−27 in one file. The shelved 790-line recogniser in `stash@{0}` was **not needed**
and is untouched.

# D20 — the fins

**Status: SHIPS. Full stack, with `hp_fn192` documented as a known residual.** Default **on**.

## The defect

`round_tool` cross-drilling a round bar/pipe/tube: the band's **inner** rim is a ruffle of
overlapping lobes folding over one another, leaving knife-thin tabs of un-cut bore wall hanging
into the hole. Manifold gives genus 1 at `$fn`=384; CGAL gives `Simple: no` at 192 while the
*unrounded* model at 192 is `Simple: yes`.

**Not a curvature problem — crease-polyline regularity.** Decisive control: same sphere, bore,
r and `$fn` — bore *along* the axis (crease a regular 96-gon) gives 0 folds; bore *across* gives
327 up to 176°. On the pipe the shortest crease segment is 0.0014 mm against a 0.33 median,
worsening as 1/`$fn`². **Cylinder detection would not fix it**; the lever is resampling the
crease polyline, which needs no curvature inference.

## What ships (worktree `agent-a1cc15393bdb9006e`, three mechanisms)

1. **The resampler.** `Chain` carries `raw` (the crease exactly as the mesh has it, never
   altered) plus stations of `at` / `pts` / `verts` (−1 where interpolated). `resampleChains()`
   places `segments` stations at **equal arc length — the same count the crease already has**,
   so density is preserved exactly. Ends stay exact mesh vertices. Runs strictly *before*
   `chainSelection`, so there is one chain-parameter space and it is the one the brush cut —
   `sectionAt`, `toSectionSpace`, `keep`, `noCorner` needed no change. Empty `at`/`pts` is the
   identity, so unresampled chains feed bit-identical inputs downstream.
2. **`chainBulges`.** Each cell's hull also takes the section interpolated to any crease vertex
   its chord passes inside of, slid onto that vertex — **wedge only**, and only away from the
   solid. Load-bearing: without it, `rot0.5` and `rot1` are genus −1 with five components.
3. **`rawStationChain`.** `checkChainSizes` sampled the fit *at the stations*, and the resampler
   steps over slivers by construction — so a blend leaving its wall only across a sliver stopped
   being sampled and started being accepted. Now the size question is asked of the raw crease,
   with brush intervals carried into that parameter.

**Watch out**: `checkChainSizes` built its junction-membership set from `chain.verts`, so a `−1`
would make *every pair of resampled chains* falsely appear to meet and skip the crowding test.
Fixed by using `chain.raw`. **Anyone touching `Chain::verts` should look for other consumers
that assume it holds real vertex indices.**

## The residual, and why it is not worth chasing

**`hp_fn192` CGAL `Simple: no / Volumes 2`** where base says yes. The 27 folds are two blobs

# D21 — the oblique self-intersecting tool

**Status: fixed, reviewed, epsilon-repaired; a scale-clamp fix was in flight at the end of the
session.** Default **on**; `OPENSCAD_FILLET_SIZEGATE=legacy` reverts.

## The defect and the mechanism

`fillet()` on crossing pipes with an **oblique thin branch** produced a shattered solid —
`Ra=10, Rb=3, r=4, tilt=-60`. Shatter window 60–75° as recorded, but **actually wider: 50–70°**
(legacy genus −4/−5/−15/−17/1 at `$fn` 48; −12/−42/−42/−10/−2 at 96), with 84° and 89° also
faulty.

`fillet()`'s round pass measures the **blended** solid. On a thin oblique branch the inner
bead's runout lip leaves genuine convex creases up to 153.22°, at which `makeRoundSection` seats
its ball 17.27 mm from the crease with a 16.81 mm setback, so cells overlap and plough through
the model — **the round tool is genus −3 before it is subtracted.**

`checkChainSizes` exists to refuse exactly this and **had measured the miss** (16.23 mm at r=4)
but **discarded the sample**: its two exemptions — chain ends, and anything within `2 × size` of
a junction — are absolute distances, while the runout lip arrives already fragmented into two-
to five-vertex chains meeting inside one 8 mm reach. **101 of 104 creases had zero testable
samples, so the gate returned "fits" meaning "I could not look."** The 60–75° window is a window
in how finely that lip fragments.

**The fix**: where the exemptions leave no testable sample, fall back to the evidence they
discarded.

## Results (worktree `agent-ad442fb5e2bfb0c44`)

- D21 oblique genus 3/−15/−42/−22 → **0/0/0/1** at `$fn` 24/48/96/192; volumes converge upward
  18446→19156 where legacy diverged 18446→17771; `>2`-face edges 6→0 and 157→0.
- The whole 50–70° band, plus 84° and 89°, to **genus 0**. Tilt 30/40/45 byte-identical with zero
  refusals; equal-radius `Ra=Rb=10` byte-identical at 48/96/192.
- `sphere-on-plate` `$fn` 192: genus −4 → **0** (real, caused by the rule, 3→8 creases refused,
  volume moving upward — the right direction for a tool that was gouging).
- Suite **1696 assertions / 84 cases**, green with the env unset **and** with `SIZEGATE=legacy`
  (an RAII `ScopedSizeGateRule` makes the new test hermetic).

## Two repairs the reviews forced

1. **The epsilon.** The fallback fired when `offExempt > 1e-9 * max(1, size)` — an epsilon copied
   from the *tested* path, which only sees mid-face samples where `offFace` is 0 or macroscopic.
   The exempt samples sit **on a face boundary**, where noise runs 1e-10 to 2e-7 mm at coordinates
   of order 40. It refused creases on **double round-off**: a plain L-bracket lost 2 of 15 creases
   on a worst miss of 2.06e-08 mm, and a 144-run census found 26 such false refusals.
   **Repaired** to `1e-4 * max(1.0, size)`: worst boundary noise measured at 1.71e-07, smallest
   genuine D21 miss 7.70e-04. Census 26 → **0**; L-bracket and T-bar byte-identical to legacy.
2. **The clamp — a genuine shatter, fix in flight.** `max(1.0, size)` hard-codes millimetres into
   a unitless modeller. For `size ≥ 1` the rule is exactly scale-invariant over six decades. Below
   1 the floor pins at an absolute 1e-4 mm and refusals bleed away — **at 1e-6 scale the gate makes
   zero blind refusals and emits the pre-fix shatter: genus −15, mesh in 19 separate components,
   identical to legacy.** Causally confirmed: removing only the clamp restores genus 0 and volume
   exactly 18898.067·s³. It bites from `size ≈ 0.8 mm`. Recommended fix:
   `floor = max(1e-4*size, C*coordinateExtent)` with `C ≈ 1e-7`; minimum acceptable, delete the clamp.

## Two things the next person must know

- **The false acceptance is real but inert.** Smallest genuine blind miss found anywhere:
  **1.832e-04 mm** at `Ra=10, Rb=2, tilt=-75, r=4, $fn=192` — 2.2× *below* the floor, and passed.
  But forcing those refusals leaves volume and genus bit-identical. No lower floor repaired any
  defect anywhere in the corpus.
- **The headroom shrinks with tessellation, which runs the wrong way against standard 1.**
  Floor-relative headroom across `$fn` 24/48/96/192 is **360× → 12× → 1.32× → 1.15×** — the floor
  is a constant fraction against evidence falling ~10× per `$fn` doubling. **Roughly one doubling
  of margin remains.** Refinement makes this worse, not better.

## Closed under D21

The sagitta is orthogonal to this defect (`C`/`TA`/`TB` precede `epsA`/`epsB`; no mode moves which
creases are refused) — **reverted out of the tree**. Capping `φ` in `makeRoundSection` leaves a stub
meeting nothing. Testing every open chain's end stations breaks the rounded cube (twelve two-vertex
chains whose end contacts legitimately step off their faces). Shrinking `junctionReach` trades one
arbitrary constant for another. **CGAL gives no independent check** — the oblique case produces no
inner bead in any mode.

**D21 and D18 are different failures.** D18 is a tangency error that refines slowly; D21 is a
self-intersecting tool in a bounded angular window that the sagitta does not move. Conflating them
produced a wrong conclusion earlier in this effort.
