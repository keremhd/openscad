## Standards the owner set — apply to every decision

1. **A defect is real only if refining `$fn` does not fix it.** Patchiness that shrinks
   with refinement is faceting and is acceptable.
2. **Practical and visual, not mathematically pure.**
3. **A visible line where two roundings meet is fine.** The bar is a *valid solid*, not
   a smooth corner.
4. **Generalisation over patchwork.** Bad but uniform beats excellent but discontinuous.
5. **Do not reverse-engineer curvature from the tessellation.** (D19's recognition stays
   on the right side of this by fitting the model's own *facet planes*, never inferring
   from facet angles.)
6. **Judge by maintenance cost, not development effort.**
7. **No user option for wall fitting** — decided. `plane + cylinder`, always on.
8. **The unit tests are not final.** "Written to make code pass." A test pinning current
   behaviour is not a constraint if the behaviour is wrong. But do not edit a pin to make
   a change pass — derive it from a hand-built ideal and say how.
9. **The design log files are dev artifacts** and will be deleted before merge.
10. **A valid solid with an unfilleted crease beats a shattered one.** A false refusal is
    the safe error; a false acceptance is the dangerous one.

## READ THIS FIRST — traps that have each cost hours

1. **Builds are silently discarded in this environment, and `make` reports "Built target"
   for binaries that do not exist.** ALWAYS verify the binary's mtime is newer than your
   last source edit before trusting any measurement. This invalidated one agent's entire
   report and cost another two full rounds. If builds misbehave, retry with
   `dangerouslyDisableSandbox`.
2. **`env $VAR ...` in zsh performs no word splitting**, so a second probe is silently
   dropped. Cost one agent a full round of measurements.
3. **This machine's locale uses comma decimals** — `atof`/`strtod` on `"0.1"` silently
   yields 0, and `printf`-family diagnostics mangle parsing. Use `istringstream` /
   `ostringstream` imbued with `std::locale::classic()`.
4. **The crease threshold is `1.5 × max($fa, 360/$fn)`, and `$fa` defaults to 12.** A model
   that sets only `$fn` is measured through an **18° threshold that cannot see its own
   tessellation**, however fine `$fn` is. Set `$fa = 360/$fn; $fs = 0.01;` in every model
   and confirm the threshold moved (5.6° at `$fn`=96). This voided an entire round of D20.
5. **A radius that does not fit is warned about, skipped, and still exports a plausible
   mesh.** An export succeeding proves nothing — read the warnings.
6. **Derive genus from the mesh, not from the ECHO output.** `>2`-face edge counts are
   weld-tolerance sensitive (205 at weld 1e-5 vs 0 at 1e-6 on the same mesh) — state your
   tolerance and read for direction and zero only.
7. **`$fn` sweeps must use a tessellated model.** `pocket.scad` and `rhomb.scad` are
   entirely planar, so sweeping `$fn` over them tests nothing. One report's whole `$fn`
   series was vacuous for this reason.
8. **Brushes are children 1+, not a `brush =` argument** (that is a parse error):
   ```openscad
   difference() { thing(); round_tool(r = 2) { thing(); brush_shape(); } }
   union()      { thing(); fillet_tool(r = 2) { thing(); brush_shape(); } }
   ```
9. **Long silent commands trip a 10-minute stall watchdog — it killed eight runs this
   session.** Usual culprits: a first full build in a fresh worktree, and an unbatched
   sweep. Run bounded batches that stream output, checkpoint every row to a file, and
   **commit as you go**. Agents were also cut by host power loss; every one resumed
   cleanly from its transcript, but **only committed work survived**.
10. **On a rotated bore, Manifold and CGAL do not evaluate the same target**
    (`hp_fn96_rot0.5` is 848 v / 1704 t under Manifold, 1104 v / 2216 t under CGAL). Cross-
    backend verdicts there are about two different solids. Phase tables must be one backend.
11. **Resource limits**: `cone_fn192` under CGAL peaks at **156 GB and OOMs in every
    binary**, including clean base. `cone_fn384` and `sph_across_fn384` cannot be exported
    at all on this machine.
12. Tooling: plain `python3` only — no matplotlib, PIL, cairosvg, rsvg-convert. ImageMagick
    exists but its SVG rasteriser has no font (`-font /System/Library/Fonts/Helvetica.ttc`).

### Nondeterminism is MUCH wider than this record assumed — and it contaminated byte-identity

Long recorded as two isolated cases:

- `rounded_cube` at `$fn` 192: three different md5s over three runs in **every** binary
  including clean HEAD; same 24156 tris, volume equal to 13 digits. (Also seen at `$fn` 96.)
- hole-in-a-flat-plate: identical volume 14857.3025669748, differing vertex order.

**Integration found it reaches far further.** `box_cube_fn96_r1`, `box_cross_fn96_r1` and
`box_L_fn96_r1` each give **three different md5s from three runs of one binary with identical
environment**. These are ordinary box models in the middle of the 144-run census.

**Consequence for the whole effort**: `cmp` byte-identity against a clean build was the primary
control almost everywhere in this work, and figures like "128 of 144 census byte-identical" were
partly measuring **run-to-run variation, not differences between builds**.

**Read the direction of the error carefully before over-correcting:**
- A reported **"byte-identical"** remains strong evidence — identity *despite* possible
  nondeterminism cannot be a false positive.
- A reported **"differs"** may be noise rather than the change under test. Several agents already
  caught this in-flight and re-ran before reporting a vertex-order difference as a regression; that
  instinct was correct and should be standard.
- **Verdicts that rest on genus and component counts are unaffected** — those were stable across
  every repeat.

**Standing rule from here**: establish the nondeterministic set for your corpus first, by running one
binary over it two or three times, then state byte-identity as *"identical outside the
nondeterministic set"* — or fall back to volume, which is stable to 13 digits.

## The design

A vertex is a **seam vertex** if some *model crease* leaving it (dihedral passing
`isFeatureAngle` at the selection threshold) is NOT in the filleted set. The owner's
principle: *does an original crease leave the vertex still sharp? If so, the two beads must
meet in a **seam that lines up with that edge** — a ball can never line up with a sharp edge,
it rounds across it. If nothing sharp leaves, a corner ball is correct.* Why the crease went
unfilleted — brush, size gate, feature-angle filter — does not matter.

**Four interacting mechanisms**, each added to stop the previous one misfiring:

1. **Local grouping** — seam vertices build no ball, so their chains stay unlinked in the
   union-find and take **per-chain** canal subtraction; elsewhere global, as before.
2. **The seam overrun** — `seamOver` = 0.10·r, extrapolating the end section past the vertex
   so beads cross transversally instead of grazing. `seamRoom` bounds it by available
   material; a **retreat fallback** stands the bead back where there is none.
3. **`arrivesStraight`** — apply the rule only where every bead reaches the vertex running
   straight (last two segments collinear to 1e-9); a one-segment crease passes.
4. **`anyServed`** — if no vertex carrying ≥2 chain ends is actually served, the union-find
   takes the pre-feature branch and everything lands in group 0, subtracting globally
   **exactly as HEAD does**.

## The mechanism behind the last blocker

The overrun continues the bead along the line its last segment lies on. On a tessellated arc
that segment is a **chord**, and a chord produced past its end **leaves the circle on the
outside** — so the extrapolation lays the bead a hair outside the wall and tangency becomes a
sliver resting on it, which is the very degeneracy the overrun exists to remove. Measured:
radius 7.996745 → 8.002908 on an r=8 cylinder, sagitta 0.006168. `seamRoom` cannot see it by
design (it ignores faces the run is parallel to).

# D19 — the subtractive scalloped ledge

**Status: route found and working; one bar unmet; a standoff attempt was in flight at the end
of the session.** Env-gated probes (`SEAT`, `WALLFACE`), default **off**.

## The defect

`round_tool` on a **curved wall** stops short and leaves un-cut original surface standing as a
ragged ledge. No bump; an under-cut. Worst **1.526 mm = 0.76 r** at Ra=10, Rb=5, r=2, `$fn`=96.
It **plateaus rather than converging** — 1.7934 / 1.6331 / 1.5261 / 1.4665 / 1.4347 at `$fn`
24/48/96/192/384, floor ≈1.40 mm — while the flat control converges as 1/`$fn`².

## Three findings that took three agents

1. **Facet seating alone makes it worse**: 1.5261 → **2.9869**, genus 0 → 16. Two independent
   implementations (a 70-line solver and the shelved 790-line recogniser) agree to four
   decimals, so **the convex regression is the seating, not any recogniser** — that retires a
   790-line suspect.
2. **A multi-vertex wall face alone does nothing**: 1.5261 → 1.5261. On HEAD's unseated
   placement the tangency point already stands off the wall, so the chord already clears the
   bulge. HEAD's ledge is not the chord — it is the setback `r·tan(φ/2)`, reaching 40 % of the
   band.
3. **Together, with the wall *recognised*, they work.**

## The recognition — 101 lines, not 790

A wall is read as the set of **facet planes** its triangles lie in, **never as a set of
points**: one plane → it is a plane and the ball is not moved; three or more distinct planes
whose normals are all square to one axis and all tangent to one cylinder about it to
1e-9·scale → it is that cylinder; anything else → unrecognised, nothing moves.

**Fitting planes rather than vertices is what makes it work**: a boolean drops new vertices on
the *flat* of a facet, so a wall's vertices lie on no cylinder even when the wall is one, while
its facet planes still do. Nothing is inferred from a facet angle — the cylinder recovered is

# D20 — the fins

**Status: SHIPS. Full stack, with `hp_fn192` documented as a known residual.** Default **on**.

## The defect

`round_tool` cross-drilling a round bar/pipe/tube: the band's **inner** rim is a ruffle of
overlapping lobes folding over one another, leaving knife-thin tabs of un-cut bore wall hanging
into the hole. Manifold gives genus 1 at `$fn`=384; CGAL gives `Simple: no` at 192 while the
*unrounded* model at 192 is `Simple: yes`.

**Not a curvature problem — crease-polyline regularity.** Decisive control: same sphere, bore,
r and `$fn` — bore *along* the axis (crease a regular 96-gon) gives 0 folds; bore *across* gives
327 up to 176°. On the pipe the shortest crease segment is 0.0014 mm against a 0.33 median,
worsening as 1/`$fn`². **Cylinder detection would not fix it**; the lever is resampling the
crease polyline, which needs no curvature inference.

## What ships (worktree `agent-a1cc15393bdb9006e`, three mechanisms)

1. **The resampler.** `Chain` carries `raw` (the crease exactly as the mesh has it, never
   altered) plus stations of `at` / `pts` / `verts` (−1 where interpolated). `resampleChains()`
   places `segments` stations at **equal arc length — the same count the crease already has**,
   so density is preserved exactly. Ends stay exact mesh vertices. Runs strictly *before*
   `chainSelection`, so there is one chain-parameter space and it is the one the brush cut —
   `sectionAt`, `toSectionSpace`, `keep`, `noCorner` needed no change. Empty `at`/`pts` is the
   identity, so unresampled chains feed bit-identical inputs downstream.
2. **`chainBulges`.** Each cell's hull also takes the section interpolated to any crease vertex
   its chord passes inside of, slid onto that vertex — **wedge only**, and only away from the
   solid. Load-bearing: without it, `rot0.5` and `rot1` are genus −1 with five components.
3. **`rawStationChain`.** `checkChainSizes` sampled the fit *at the stations*, and the resampler
   steps over slivers by construction — so a blend leaving its wall only across a sliver stopped
   being sampled and started being accepted. Now the size question is asked of the raw crease,
   with brush intervals carried into that parameter.

**Watch out**: `checkChainSizes` built its junction-membership set from `chain.verts`, so a `−1`
would make *every pair of resampled chains* falsely appear to meet and skip the crowding test.
Fixed by using `chain.raw`. **Anyone touching `Chain::verts` should look for other consumers
that assume it holds real vertex indices.**

## Results

- **Fold census 0** at every facet phase and every `$fn` tried, against base 96–562.
  `$fn` 97/98/100/128 → 0/0/0/0; rot 0.5/1/1.875/2.5/3.75 → all 0.
- **D19 ledge identical to base in every cell** at `$fn` 24/48/96/192/384 — load-bearing, an
  earlier round died on exactly this.
- CGAL repairs: `hp_fn96` no → **yes**; `sph_across_fn48` 6 volumes → **2**; `cone_fn24` no/3 →
  **yes/2**; `hp_fn96_rot0.5` restored to yes/2 with the base's exact 6-of-12 refusal.
- Controls identical sha in base / built / fix6. Suite **1688/83**. No timing regression.
- Inertness check passed: the debug overlay differs on pipe, rotated pipe, cone and sphere, and
  is **byte-identical on the tube**, whose crease is a regular circle and which nothing should
  touch. Every claimed win fired; the control provably did not.

## The residual, and why it is not worth chasing

**`hp_fn192` CGAL `Simple: no / Volumes 2`** where base says yes. The 27 folds are two blobs
0.03 mm across on the bore-mouth band, and the tangle is already in the tool before the
difference (23 verts / 54 tris in a 0.10 mm ball against base's 3 / 14) — the bead's own canal
grazing itself. Drop the threshold to 2° and the neighbourhood is **eight-fold symmetric with a
9° fold at all eight spots**; the two blobs are the two symmetry images that rounding tipped
past 150°. **Translating the same solid by `[0.1234, 0.2345, 0.3456]` gives 1 fold and CGAL
`Simple: yes / 2`** off the same 1696-vertex target.

**`cone_fn192` genus 4 is not a regression.** Across bore phases (rigid rotations of one solid)
base gives 3 / 3 / **4** / 3 and round 4 gives **4** / 4 / 3 / 3, against a bare target of 3
everywhere — the base produces the same spurious handle, one phase over. Folds meanwhile go
1372/1050/1358/1354 → 3/0/9/0.

Unmeasured: CGAL on `hp_fn384`; `cone_fn192` under CGAL (OOM); the phase sweep at `$fn` 384;
the translation sweep on the cone; whether the grazing contact is predictable from the crease
without inferring curvature (nothing suggests it is).

# D21 — the oblique self-intersecting tool

**Status: fixed, reviewed, epsilon-repaired; a scale-clamp fix was in flight at the end of the
session.** Default **on**; `OPENSCAD_FILLET_SIZEGATE=legacy` reverts.

## The defect and the mechanism

`fillet()` on crossing pipes with an **oblique thin branch** produced a shattered solid —
`Ra=10, Rb=3, r=4, tilt=-60`. Shatter window 60–75° as recorded, but **actually wider: 50–70°**
(legacy genus −4/−5/−15/−17/1 at `$fn` 48; −12/−42/−42/−10/−2 at 96), with 84° and 89° also
faulty.

`fillet()`'s round pass measures the **blended** solid. On a thin oblique branch the inner
bead's runout lip leaves genuine convex creases up to 153.22°, at which `makeRoundSection` seats
its ball 17.27 mm from the crease with a 16.81 mm setback, so cells overlap and plough through
the model — **the round tool is genus −3 before it is subtracted.**

`checkChainSizes` exists to refuse exactly this and **had measured the miss** (16.23 mm at r=4)
but **discarded the sample**: its two exemptions — chain ends, and anything within `2 × size` of
a junction — are absolute distances, while the runout lip arrives already fragmented into two-
to five-vertex chains meeting inside one 8 mm reach. **101 of 104 creases had zero testable
samples, so the gate returned "fits" meaning "I could not look."** The 60–75° window is a window
in how finely that lip fragments.

**The fix**: where the exemptions leave no testable sample, fall back to the evidence they
discarded.

## Results (worktree `agent-ad442fb5e2bfb0c44`)

- D21 oblique genus 3/−15/−42/−22 → **0/0/0/1** at `$fn` 24/48/96/192; volumes converge upward
  18446→19156 where legacy diverged 18446→17771; `>2`-face edges 6→0 and 157→0.
- The whole 50–70° band, plus 84° and 89°, to **genus 0**. Tilt 30/40/45 byte-identical with zero
  refusals; equal-radius `Ra=Rb=10` byte-identical at 48/96/192.
- `sphere-on-plate` `$fn` 192: genus −4 → **0** (real, caused by the rule, 3→8 creases refused,
  volume moving upward — the right direction for a tool that was gouging).
- Suite **1696 assertions / 84 cases**, green with the env unset **and** with `SIZEGATE=legacy`
  (an RAII `ScopedSizeGateRule` makes the new test hermetic).

## Two repairs the reviews forced

1. **The epsilon.** The fallback fired when `offExempt > 1e-9 * max(1, size)` — an epsilon copied
   from the *tested* path, which only sees mid-face samples where `offFace` is 0 or macroscopic.
   The exempt samples sit **on a face boundary**, where noise runs 1e-10 to 2e-7 mm at coordinates
   of order 40. It refused creases on **double round-off**: a plain L-bracket lost 2 of 15 creases
   on a worst miss of 2.06e-08 mm, and a 144-run census found 26 such false refusals.
   **Repaired** to `1e-4 * max(1.0, size)`: worst boundary noise measured at 1.71e-07, smallest
   genuine D21 miss 7.70e-04. Census 26 → **0**; L-bracket and T-bar byte-identical to legacy.
2. **The clamp — a genuine shatter, fix in flight.** `max(1.0, size)` hard-codes millimetres into
   a unitless modeller. For `size ≥ 1` the rule is exactly scale-invariant over six decades. Below
   1 the floor pins at an absolute 1e-4 mm and refusals bleed away — **at 1e-6 scale the gate makes
   zero blind refusals and emits the pre-fix shatter: genus −15, mesh in 19 separate components,
   identical to legacy.** Causally confirmed: removing only the clamp restores genus 0 and volume
   exactly 18898.067·s³. It bites from `size ≈ 0.8 mm`. Recommended fix:
   `floor = max(1e-4*size, C*coordinateExtent)` with `C ≈ 1e-7`; minimum acceptable, delete the clamp.

## Two things the next person must know

- **The false acceptance is real but inert.** Smallest genuine blind miss found anywhere:
  **1.832e-04 mm** at `Ra=10, Rb=2, tilt=-75, r=4, $fn=192` — 2.2× *below* the floor, and passed.
  But forcing those refusals leaves volume and genus bit-identical. No lower floor repaired any
  defect anywhere in the corpus.
- **The headroom shrinks with tessellation, which runs the wrong way against standard 1.**
  Floor-relative headroom across `$fn` 24/48/96/192 is **360× → 12× → 1.32× → 1.15×** — the floor
  is a constant fraction against evidence falling ~10× per `$fn` doubling. **Roughly one doubling
  of margin remains.** Refinement makes this worse, not better.

## Closed under D21

The sagitta is orthogonal to this defect (`C`/`TA`/`TB` precede `epsA`/`epsB`; no mode moves which
creases are refused) — **reverted out of the tree**. Capping `φ` in `makeRoundSection` leaves a stub
meeting nothing. Testing every open chain's end stations breaks the rounded cube (twelve two-vertex
chains whose end contacts legitimately step off their faces). Shrinking `junctionReach` trades one
arbitrary constant for another. **CGAL gives no independent check** — the oblique case produces no
inner bead in any mode.

**D21 and D18 are different failures.** D18 is a tangency error that refines slowly; D21 is a
self-intersecting tool in a bounded angular window that the sagitta does not move. Conflating them
produced a wrong conclusion earlier in this effort.

# D22 — the crease threshold cannot see `$fs` — NEW, diagnosed, unfixed

**Status: root cause established and located; no fix attempted. Pre-existing on clean
`944e0cbef`, not an integration effect.** This is the most user-visible defect found so far:
**at stock defaults, on the commonest shape in OpenSCAD, the operator rounds every facet seam.**

## The defect

With no `$fn` set, `fillet()` on a plain tee of two `d=10` cylinders puts a **burr on every rim**.
Setting `$fn` to *any* value — 8, 16, 32, 50 — makes it correct. The owner found this by hand;
the first diagnosis offered was wrong because the reproduction wrote `$fn = 16` at the top of the
file, which is one of the configurations that works. **`$fn = 16` and no `$fn` are not the same
model, and the difference between them is the whole defect.**

## The mechanism

`CurveDiscretizer::getMaxSeamAngle()`, `src/core/CurveDiscretizer.h:52`:

```cpp
return std::max(fa, fn > 0 ? 360.0 / fn : 0.0);
```

`FilletBuilder.cc:3542` takes `1.5 ×` that as the crease threshold — the angle separating a real
feature edge from a curve-tessellation seam. **It accounts for `$fa` and `$fn` and not for `$fs`**,
but `$fs` is what sets the fragment count at defaults:

```
fragments = ceil(max(min(360/$fa, 2*pi*r/$fs), 5))
```

For `d=10` at stock defaults: `min(30, 15.708)` → **16 fragments → real seam 22.5°**, against an
assumed 12° and a threshold of 18°. Every wall seam clears the threshold and is filleted.

**`$fs` binds whenever `r < 360*$fs / (2*pi*$fa)` = 9.55 mm at stock defaults**, so nearly every
curved feature under ~19 mm diameter in a default-settings model is affected. The `5`-fragment
floor is a second uncovered path (72° seam at any threshold).

**Why every explicit `$fn` works**: `fragments == $fn` exactly, so the assumed seam equals the real
one, ratio 1.0 against a 1.5 margin — safe at every value, which is why `$fn = 8` is as clean as 50.

## The measurement

Crease counts on the owner's model (`fillet(r=1)` over the two-cylinder tee), predicted from the
binding term before being read:

| header | binds | real seam | threshold | creases selected |
|---|---|---|---|---|
| *(defaults)* | `$fs` | 22.5° | 18° | **95**, 30 refused |
| `$fa=5;` | `$fs` | 22.5° | 7.5° | **75**, 6 refused |
| `$fs=0.5;` | `$fa` | 12° | 18° | 8, 5 refused |
| `$fs=0.5; $fa=5;` | `$fa` | 5.7° | 7.5° | 28, 13 refused |
| `$fn=16;` | `$fn` | 22.5° | 33.75° | **clean, no warning** |
| `$fn=50;` | `$fn` | 7.2° | 18° | **clean, no warning** |

The model has **two** creases. Note `$fa=5` is *worse* than the default: asking for a smoother
model lowers the threshold while `$fs` holds the mesh coarse. That inversion is the sharpest
statement of the fault.

Controls: a lone `cylinder(d=10, h=20)` under `fillet(r=2)` is clean at `$fn` 16 and 64, so the
rims are not the problem; `cube`, boss-on-plate, L-bracket and an unequal-diameter tee are all
genus 0 with no warnings at explicit `$fn`. The old main-checkout binary (`944e0cbef` plus the
superseded sign-rule diff) reads the **same 95 creases**, so this predates all four defects.

## Two fix directions, neither costed

1. **Have the discretizer report the coarsest seam it actually emitted.** Every primitive already
   calls `get_fragments_from_r`; recording the worst seam during the render makes the threshold
   exact by construction and needs no radius at the query site. Plumbing, but correct-by-construction.
2. **Take the radius at the call site** — `getMaxSeamAngle(r)` at the smallest curvature the target
   carries. Cheaper, but the operator would have to derive that radius from the mesh, which brushes
   against standard 5.

**Not measured**: whether the threshold is the only consumer of `getMaxSeamAngle` that is wrong for
this reason; what a corrected threshold does to the D17–D21 corpora (every one of those models sets
`$fn` explicitly, so **none of them exercise this path** — which is exactly why nothing caught it);
and whether the 5-fragment floor produces a distinct failure or the same one.

## Repro

```openscad
// burrs on every rim; delete the $fn line and it is correct at any value
fillet(r=1) {
    union() {
        cylinder(d=10, h=20);
        translate([0,0,10]) rotate([0,80,0]) cylinder(d=10, h=10);
    }
}
```

# D23 — the size gate drops oblique curved-wall creases on impossible misses — NEW, unfixed

**Status: characterised across two model families, mechanism not yet proved, no fix attempted.**

**Read the framing correction first.** This was initially written up as "the equal-radius crossing",
on a diameter sweep at one tessellation. **That framing was wrong and the owner rejected it**: with
`$fn` set the equal-radius model works. A sweep across ten explicit `$fn` values shows the real
shape of the fault — equal radius is not the trigger, it only raises the hit rate.

## The defect

`checkChainSizes` refuses a crease reporting that "the blend would leave the surface it is meant to
meet" by an amount that is **geometrically impossible** — up to **41.7 mm for an `r=1` fillet on a
20 mm part** — and the whole crease is then dropped, silently leaving it sharp. The refusals are a
**tessellation lottery**: same model, same radius, neighbouring `$fn` values disagree.

`fillet(r=1)` on the tee, both branches oblique at 80°, `d=10` body:

| `$fn` | 24 | 32 | 40 | 50 | 60 | 64 | 72 | 80 | 96 | 120 |
|---|---|---|---|---|---|---|---|---|---|---|
| branch `d=10` | ok | ok | 2/5 | ok | 4/7 | **38/40** | 4/7 | **31/36** | 10/13 | 4/7 |
| branch `d=8` | ok | ok | ok | ok | **12/15** | ok | ok | ok | ok | ok |

(refused / selected; "ok" is no warning). Worst misses quoted: 8.10 at `d=10`/`$fn` 64, 14.8 at
`$fn` 80, and **41.7 at `d=8`/`$fn` 60** — on an `r=1` fillet.

**Equal radius is a rate, not a trigger**: 7 of 10 tessellations refuse at `d=10` against 1 of 10 at
`d=8`. `$fn`=50 — the value the owner happened to pick — is one of the good ones at both diameters.

## The second family: a cylinder plunging obliquely into a flat face

`Untitled1.scad` as the owner then rewrote it — `cube(15, center=true)` with the same 80° cylinder
whose base sits above the cube and whose lower rim dips to `z=5.076`, through a top face at 7.5:

```openscad
$fn = 50;
fillet(r = 0.5) union() {
    cube(15, center = true);
    translate([0, 0, 10]) rotate([0, 80, 0]) cylinder(d = 10, h = 10);
}
```

Every cube edge and every cylinder rim rounds correctly and **the cube-to-cylinder junction gets no
fillet at all** — one crease refused, at `[0.6432, 4.28, 7.5]`, on the cube's top face.

**Here it is refused at every radius and every tessellation tried, and the miss does not converge:**

| r | 0.1 | 0.2 | 0.3 | 0.5 | 0.8 | 1 | 1.5 | 2 |
|---|---|---|---|---|---|---|---|---|
| miss | 0.0216 | 0.0345 | 0.0333 | 0.0131 | 0.0481 | 0.1136 | 0.4052 | 0.8096 |

| `$fn` | 16 | 32 | 50 | 64 | 100 | 200 |
|---|---|---|---|---|---|---|
| miss | 0.1363 | 0.0306 | 0.0131 | 0.0030 | 0.0041 | **0.1020** |

Refinement takes it down two orders and then **back up at `$fn` 200** — non-monotone, never zero.
A miss of 0.0216 mm for an `r=0.1` blend against a flat 15 mm face cannot be a real fit failure;
the quantity is not scaling with the blend. **Control: the same cylinder plunging vertically
(`tilt=0`) is clean at `$fn` 50 and 100**, so it is the oblique arrival, not the cylinder-meets-plane
crease as such. `$fn`=64 also reads **genus 3** on this shape.

## Refusal granularity is the whole chain — one bad sample discards good geometry

On the cube shape the cylinder leaves the solid through **two** faces: the top (`z=7.5`) and the
front (`x=7.5`). Both junctions come out sharp, but **only one crease is reported refused**, and it
is on the top face. The front-face section is collateral. Isolated, it is perfect:

| model | result |
|---|---|
| `cube([15,15,34])` — cylinder exits the **front face only** | **no warning, fillet built, clean** (see render) |
| `cube([26,15,15])` — cylinder exits the **top face only** | refused, `[0.6432, 4.28, 7.5]`, miss **0.0131448** — the same point and the same digits as in the original |
| original `cube(15)` — exits **both** | one refusal, top face; **both** sections unfilleted |

The front-face crease carries a 80–82° dihedral over twelve edges and fits at `r=0.5` on its own.
It is lost because the intersection curve is **one closed loop** that crosses the cube's top-front
edge, so top and front are sections of a single chain, and refusal is **per chain**. The deduction
is from the refusal count: if they were two chains and only one was refused, the other would have
been built, and it was not.

`FilletBuilder.cc:3756` states the policy deliberately — refuse "one crease at a time" rather than
quietly clamp, because a clamp would have to be agreed across the whole connected network. **That
argument is about clamping the radius; it does not argue for discarding the parts of a chain that
fit.** The practical effect is that a sub-millimetre false reading at one station removes a whole
visible feature. Combined with the impossible misses above, this is what makes the operator feel
unusable on ordinary models: the failures are large, and they are triggered by tiny numbers.

**Worth investigating as its own fix, and possibly ahead of the miss itself**: splitting a refused
chain at the offending station and building the sections that fit would turn every defect in this
section from a missing feature into a locally missing millimetre. Not attempted, not costed, and it
interacts with junction handling and with the brush's parameter space.

## Why this is one defect and not two

Both families are creases where one wall is a **tessellated cylinder met obliquely**; both are
refused by the same `OffFace` branch; both report misses that do not scale with `r` and do not
converge with `$fn`. The likeliest mechanism — untested — is the one D19 named for a different
symptom: **contact is tested against *bounded* triangles, so a contact point that runs off the end
of a facet reads as "off the surface"**, which on an oblique crease happens somewhere along almost
any polyline. D21's epsilon repair covers the same class at the 1e-7 scale; these misses are 1e-2
to 1e+1, five to nine orders larger, so **that repair does not reach them**.

## Note where this was hiding

The handoff already calls `Ra = Rb = 10` "the singular equal-radius case", and D21 used it as a
**byte-identity control** at `$fn` 48/96/192 — measured only for whether it *changed*, never for
whether it was *right*. **A control that pins a wrong answer** belongs in the instrument table in
spirit if not in form.

**Severity**: mostly the mild kind — the solid stays valid and the user simply does not get the
fillet, which standard 10 calls the safe error. But `$fn` 64 on the cube shape is genus 3, and
`r=2` there is genus −1, so it is not uniformly benign.

**Not measured**: the facet-boundary mechanism itself (inferred, not shown); cones and spheres;
whether D20's resampler changes the refusal counts; and whether the impossible miss values come
from a bad sample or a bad comparison.

# D24 — a bead whose neighbour was refused is truncated and then left open — NEW, unfixed

**Status: reproduced with an all-planar model, mechanism inferred from the existing D15 rule, no fix
attempted.** Found by the owner as "a shoulder, a strange corner point — rounding stops short of it
and doesn't get a ball, it just stops sharply".

## The symptom

Where the cylinder crosses the cube's top-front edge, the **convex bead running along that cube edge
stops dead in mid-air and is capped with a blunt flat face**, short of the vertex. Nothing closes it.
It is not a seam, not a ball, not a runout — the rounding simply ends.

## It does not need a cylinder

```openscad
$fn = 50;
fillet(r = 0.5) union() {
    cube(15, center = true);
    translate([0, 0, 10]) rotate([0, 80, 0]) translate([-4, -4, 0]) cube([8, 8, 10]);
}
```

Boxes only, every face flat, no tessellation anywhere in the junction — and **the cube-edge bead
still stops in mid-air with a blunt end and a visible gap** before the tilted box. **Use this as the
repro**, not the cylinder one: it removes curvature, `$fs`, the size gate's off-face test and D22
from the picture in one step.

(That model also refuses two creases of its own — `[7.5, 4, 7.44]` missing by 0.052, and a crowding
refusal at `[7.5, -4, 7.261]` — which is worth noting separately: **D23's "impossible miss" is not
confined to curved walls either.** A box meeting a box at 0.052 mm of miss for an `r=0.5` blend
deserves its own look.)

## The likely mechanism

D15 built the corner cell "where **two** bead ends arrive". Here only one arrives: the neighbouring
crease produced no bead, because D23 refused it. But the surviving bead is **still truncated as
though a neighbour were coming** — spine truncation happens at the junction regardless — so it is
shortened *and* left unclosed. The two halves of the old design disagree about whether the
neighbour exists.

**Not the seam rule.** `OPENSCAD_FILLET_LOCALGROUP` is default-off, so D17.3's seam-vertex path is
not running in a stock build; this is the plain truncation path. Worth re-checking with the rule on
once the env vars go, since the seam rule reaches the same vertex by a different route and its
design note explicitly says the *reason* a crease went unfilleted — "brush, size gate, or
feature-angle filter" — does not matter.

## Why it deserves its own number rather than being folded into D23

Refusals will always exist — standard 10 says a refusal is the safe error. So "what closes a bead
whose neighbour was refused" is a question that outlives any particular refusal bug, and it has its
own fix (do not truncate against a neighbour that was never built, or cap the end properly). Fixing
D23 would hide this instance without answering it.

**Not measured**: whether the truncation or the missing cap is the larger part of the visual defect;
whether the same thing happens when a crease is dropped by the feature-angle filter or by a brush
rather than by size; and what the seam rule does here with `LOCALGROUP=1`.

## The `Chain::verts` audit — done

Report: `audit-chainverts/work/CHAIN-VERTS-AUDIT.md`, branch `audit-chain-verts`.

**Why it was commissioned**: `Chain::verts` used to hold real mesh vertex indices; D20's resampler
puts **`-1`** at every interpolated station. The same fault was then found and fixed **three separate
times, always at integration, never by the branch that introduced it** — each branch correct alone,
wrong the moment D20 was present. Note the shape of the third one: `filletedEdges` was "fixed" with a
guard that *skips* `-1` pairs, which stops the crash and **silently changes the answer** (a filleted
crease reads as unfilleted, so the seam rule invents a vertex). **A crash-guard is not a fix.**

**Result: 5 findings, none producing a wrong answer today.** The residual risk in this class is type
and documentation, not arithmetic.

1. `chainJunctions` stores `-1` as a "next station" but never dereferences it — only `nbrs.size()` is
   read. Repaired by making the map a **count**, removing the poisoned value rather than guarding it.
2. **A false comment**: `FilletBuilder_internal.h` claims *"the two ends are always exact mesh
   vertices, resampled or not."* **Untrue for closed chains** — the resampler pins the last station
   only `if (!closed)`, so a ring's `verts.back()` is `-1`. It would crash; safe today only because all
   twelve production `.back()` reads happen to be closed-guarded, **which nothing stated**. Corrected.
3. `ChainContact::vert` is written from `verts[i]` and **never read anywhere**. Recommend deleting it.
4. `filletedEdges`'s dead crash-guard and the paragraph arguing for the skip that the line below
   contradicts — both deleted, so nobody reads it as precedent.
5. A test that would crash, unreachable because **no test anywhere calls `resampleChains`**.

**Reachability was established by construction, not argument** — and this is the methodological point.
A bore through a round bar with the mouth ring clipped so the resampled crease arrives *open* puts four
`-1`s into the junction map with no env var set. **Both natural candidate models failed to reach it,
for two different reasons** (one resamples open chains but the size gate refuses them; the other
reaches the map but resamples nothing). So *"the corpus never showed it"* would have been the wrong
conclusion — which is the trap this effort has fallen into repeatedly, in both directions.

### The closing-edge bug — unreachable, D17.3's own, fixed anyway

`filletedEdges` omitted a closed chain's closing edge (`run[n-1] → run[0]`), which could invent a seam
vertex on a fully filleted ring — the exact misfire the seam rule exists to avoid, and **a wrong answer
rather than a wasted classification**, since it suppresses a corner ball that is correct.

**Unreachable, on two independent arguments.** (i) `seamVertex` is never *asked* at a ring vertex: all
five call sites pass either `j.vert` (junctions come only from open-chain ends) or a vertex from
`chainsAt` / `chains[ci].verts.front()/back()`, both of which `continue` on `chain.closed`. (ii) Even
without those guards, **a ring shares no vertex with any open chain** — `buildChains` starts an open
walk at every crease-degree ≠ 2 vertex and consumes its edges, and a walk crossing a degree-2 vertex
consumes both; rings are the leftovers. That is also *why* `grid100` stays one group.

**No shipping defect opens it**: D20 changes which *stations* a chain has, never whether it is closed,
and `filletedEdges` reads `rawRun()`; D21 only deletes chains; D19 touches no chain topology.

**And it is D17.3's own bug, not an inherited one** — `git show 944e0cbef:…/FilletBuilder.cc` contains
neither `filletedEdges` nor `creaseLeavesUnfilleted`; both arrive with the seam rule.

Fixed regardless (`b724c35ff`), because the reasoning above was the only thing standing between it and
a wrong answer and it was **written down nowhere**. Suite 1709/85 green env-unset and with
`LOCALGROUP=1`; volume and triangle count identical on nine ring-carrying model/environment pairs
including `grid100` (1287035.925051632, a hundred closed chains) — not one digit moves, exactly as the
structural argument predicts.

### RECOMMENDED FOLLOW-UP — change the type so this cannot recur

- **R1**: make `verts` **private**; expose `endVert(bool front)` (asserting `!closed`) and
  `stationCount()`. `rawRun` / `param` / `point` / `inEdge` / `outEdge` / `rawMid` already cover
  everything else. Every site then either compiles through an accessor or **stops compiling** — and
  `endVert` asserting `!closed` makes finding 2 *unwriteable*.
- **R2**: `verts.size() == rawRun().size()` holds today **only by accident** — the resampler happens to
  emit one station per existing segment. **Three size-based consumers depend on it and nothing enforces
  it**, and D19's rejected fixed-count resampling would have broken it silently.
- **R3**: add one test that actually calls `resampleChains` and pins the invariants. That alone would
  have caught all four instances at the point they were written.
