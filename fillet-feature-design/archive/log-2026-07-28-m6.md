# 2026-07-28 — M6: the fillet cases become real tests

The wedge tools were green in `fillet-tests/` but invisible to `ctest`. M6 gives
them a home in the repo's own regression machinery and moves the containment
comparison off the shell.

## What landed

**Two regression cases**, auto-globbed into 16 test instances:

- `tests/data/scad/3D/features/chamfer-tool-tests.scad` — the inner corner, and a
  boss standing on a plate, whose base ring is a closed chain.
- `tests/data/scad/3D/features/bevel-tool-tests.scad` — a cube (all twelve convex
  edges at once) and a cylinder, whose two rims are closed chains and whose side
  seams must stay sharp.

Each draws the tool alone next to the applied result. A picture of the applied
result alone hides most of what can go wrong — a tool that is 10 % too small
still looks like a chamfer once it is unioned in.

**The containment comparison in Catch2**: `src/geometry/fillet/FilletCompare_test.cc`.

## The comparison is cheap in C++, and that changes what it can cover

The shell suite dilates through `minkowski()`, which has no Manifold path and
falls back to CGAL's Nef kernel. That is the reason ring cases run at `$fn = 48`
and every check is bounded by a timeout.

Against Manifold directly, dilation is one convex hull per triangle. A triangle
plus a cube is the hull of the 24 points you get by offsetting each corner of the
triangle to each corner of the cube, and a solid's Minkowski sum with a convex
body is the solid unioned with the sums of its boundary triangles — so this is
exact, not an approximation, and it costs one `BatchBoolean` over a few hundred
hulls. Four cases run in about two seconds, against seconds *per check* in the
shell.

The calibration came along with it, because an instrument that cannot fail proves
nothing: two tessellations of one cylinder agree within the coarse one's chord
error and not within a tenth of it; a solid never agrees with an empty one (the
case that separates "matches" from "the operator did nothing"); a wedge 20 % too
deep is caught.

The shell suite is not now redundant. Its six columns are how a wrong corner gets
*diagnosed*; a Catch2 failure names the case without showing it.

## The backend question resolved the other way

`test-design.md` §3 expected fillet `.scad` files to render empty under
`--backend=cgal`, and planned to exclude them from the CGAL variants. The premise
was wrong: the "fillet tools require the Manifold backend" warning sits behind
`#ifdef ENABLE_MANIFOLD`, a **compile-time** guard. On a Manifold-enabled build
the CGAL backend still builds the tool through Manifold and renders it.

Measured rather than assumed: preview and throwntogether come out byte-identical
on both backends, and so does the chamfer render — one shared baseline.

The bevel render does not, and the reason is worth keeping. The tool overshoots
each wall by `eps` so it crosses the surface at 90° instead of lying on it. Those
slivers are fine in Manifold and not representable as a Nef polyhedron: CGAL
throws an assertion, discards 14 facets, and shades the cut faces as back-facing.
The shape is right; the CGAL rendering of it is not.

So the bevel case joins `RENDER_DIFFERENT_EXPECTATIONS` — the same list, for the
same reason, as `issue1137.scad` — instead of being hidden from one backend.
Committing a baseline that looks wrong is the smaller cost: excluding the case
would have buried a real difference behind a passing suite, and this way a change
in either direction still shows up. The `.scad` says so in its header comment, so
nobody reads the green faces as a bug in the tool.

Exclusion is still used, but where it was actually warranted: in the
`NOT ENABLE_MANIFOLD` block, where the compile-time fallback makes every image
wrong. The `.csg` dump keeps running there — the nodes parse and serialise
regardless of backend, which is the M0 acceptance criterion, now pinned.

## The coverage sweep that came with it

Setting up the regression layer was the moment to ask what the unit layer had
been missing since M2, and it had four gaps, all of them things a picture reports
badly:

- **The derived threshold.** `getMaxSeamAngle()` was added at M2 and never
  asserted, and every classification test picked a threshold by hand. Now the
  number is pinned (12° at default `$fa`; 22.5° at `$fn = 16`; `$fa` wins again
  at 64) *and* so is what it buys: a cylinder's side seams stay rejected at 8, 16
  and 64 facets, which is the case a fixed constant gets wrong — at `$fn = 8` the
  seams are 45°, so anything below 67.5° would fillet them.
- **The φ→180 guard.** A V-groove whose walls meet at half a degree makes
  `d = r/cos(φ/2)` run away; the frame has to come back invalid. The test also
  asserts the angle it was refused at, so a refusal for some unrelated earlier
  reason cannot pass as the guard working.
- **Empty and non-positive input.** A setback of zero or less, and a chain list
  with nothing in it, both build nothing.
- **The debug overlays.** Untested since M3/M4. Asserted by colour class, which
  is what the overlay is read for: cube one class, L-shape two, coarse cylinder
  two (rims and rejected seams) — plus the null returns the caller relies on.

Two things are left to the regression layer on purpose: the node factory, whose
assertion is the `.csg` dump baseline (all four names, the resolved `$fn/$fa/$fs`
and `r`/`t`, no second copy of the expected string in C++), and `buildFilletTool`
itself, which would need a `ModuleInstantiation` to exercise three branches over
functions that are each tested directly.

## What M6 did not promote

The §1 sanity case — hole mouth == `annulus_prism − torus` — is a `round_tool`
case, and the rounded tools still emit nothing. It is M7's first `.scad`, which
is exactly what establishing the pattern here was for. `expectations.txt` is
untouched: nothing changed state.
