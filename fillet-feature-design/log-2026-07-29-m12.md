# 2026-07-29 — M12: the `fillet()` wrapper

Built as the item specified: a C++ node, `difference(union(child, fillet_tool),
round_tool)`, with the preview passthrough on by default. What follows is the
three places where building it taught something the item did not say.

## A fifth `FilletType`, not a fifth node class

`fillet()` is a `FilletNode` with `type = APPLY`, rather than a new class. The
reason is `CSGTreeEvaluator::visit(FilletNode)`, which already exists and already
does the right thing: it forces geometry evaluation and inserts the result as a
single leaf, because a node that inspects its child's mesh cannot be expressed as
a CSG union/difference of its children. The wrapper needs exactly that and
nothing else, so a second node class would have bought a second `VISITABLE`, a
second `NodeVisitor` entry and a second copy of that visit, to reach the same
place.

The cost is `buildFilletTool` no longer reading the sign off the node — it takes
a `FilletType` argument, since one `APPLY` node asks it for one tool of each
sign. Three lines in the builder; nothing else calls it, as the unit tests reach
the internals directly.

## The passthrough belongs at instantiation, not in the evaluator

The item says "with `$preview` true the node returns its child untouched" without
saying where. Doing it in the evaluator is the wrong half of the program:
`CSGTreeEvaluator` would still find a `FilletNode` in the tree and force the
child through a full geometry evaluation — merging the mesh, rebuilding edge
adjacency — to produce a model that needed none of it. The whole point of the
default is that preview should not pay for the fillets.

So the builtin returns a `GroupNode` over child 0 instead of constructing a
`FilletNode` at all, which is also exactly what the equivalent SCAD module does.
Child 0 only: children 1+ are selection brushes for the tools, and passing them
through would put the brush in the model.

`$preview` reads off `Parameters` the same way `$fn` does — it is a config
variable, so `lookup` sends it to the session's special-variable stack. If it is
unset it comes back undef, which reads as false, which builds. No `RenderVariables`
plumbing, as the item predicted.

## The dump runs the preview renderer

The acceptance asks for both "shows the bare cube under F5" and "a `.csg` dump
line for the node". Those are in tension and the item did not notice: `dump`
invokes the CLI with no `--render`, the default renderer is OpenCSG, and
`canPreview(CSG)` is true — so `$preview` is set for the dump, and a node that
passes through under preview leaves nothing in the `.csg` but a `group()`.

Resolved by putting a `disable_preview = false` model in the regression file. It
is the only invocation that reaches the dump, and it is independently the
acceptance criterion for the opt-out, so one model discharges both.

## What the regression file pins, and why it is a boss and not an L

`tests/data/scad/3D/features/fillet-tests.scad` — four models, and the harness
globs it into dump, render, preview and throwntogether on both backends without
any registration.

The **preview** baseline is the valuable one and is the reason the file earns
its place: three bare models and one filleted, which is the passthrough and its
opt-out in a single picture. Nothing else in the suite could pin that, since the
tool nodes deliberately never pass through.

First draft used the L from `fillet-tool-tests.scad` and had to be thrown away.
Its only inner crease is one short vertical edge, so at `r = 2` the bead is a few
pixels and `inner = false` was indistinguishable from the default — two of the
four models pinning nothing a human could check. A boss on a plate has a closed
concave ring at the base and convex edges everywhere, so both halves have
something obvious to do and all four models read apart. Volumes, measured while
choosing: bare 2040, inner only 2048.8, outer only 1875.7, both 1884.5 — the two
halves compose to within 0.02 of acting independently.

Deliberately **not** written: a unit test asserting `fillet(r) cube()` equals
`difference(union(cube, fillet_tool), round_tool)`. It restates the
implementation in the test's own words and would go green for any composition the
two happened to agree on. `FilletCompare_test.cc` already pins the tool solids
the composition is made from, and the picture pins the composition.

## The empty-selection warning had to learn about the wrapper

D5 established that selecting nothing must be said out loud. Applied unchanged to
the wrapper, `fillet(r=2) cube();` — the first line of every doc page this
feature will ever have — warns "no concave edge of the target turns more than
18.0 deg … `round_tool` takes those", which is advice to do the thing the node is
already doing with its other half.

The rule that replaced it, for `APPLY` only:

| | says |
|---|---|
| both halves on, other sign has creases | nothing — the other half is working |
| both halves on, no creases of either sign | once, from the inner half |
| one half on, creases are all the other sign | names `inner =`/`outer = true` |

The middle row's "once" is why the speaking half is picked explicitly rather than
letting both warn. The bottom row is the case worth adding beyond the item: a
half working alone *is* the whole operator, so `fillet(r=2, outer=false) cube();`
genuinely does nothing, and silence there is the exact failure D5 was written
against. The four tool nodes keep their original messages untouched.

## `min_angle=`, beyond the four the item names

Added. The item lists four parameters, but the DOC section calls `min_angle=` the
escape hatch for the threshold picking the wrong edges, and an escape hatch you
can only reach by abandoning the entry point and writing the composition out by
hand is not one.

It goes to both halves. The threshold is a statement about which edges of the
*target* are features, so it cannot depend on which sign is being built, and a
`fillet()` whose two halves disagreed about what counts as a crease would be
incoherent. Verified through the real node — the diagnostic line reports the
threshold it actually used, and both halves report the requested value:

```
fillet(r=2)                -> selects 0 concave / 12 convex at 18.0 deg
fillet(r=2, min_angle=30)  -> selects 0 concave / 12 convex at 30.0 deg
fillet(r=2, min_angle=10)  -> selects 0 concave / 12 convex at 10.0 deg
```

**Its coverage is the dump line and nothing more, on purpose.** What a threshold
does to a selection is already pinned in `FilletBuilder_test.cc`, where it is
milliseconds and exact; repeating that as a render and an eye would be slower and
worse. What was *not* covered is the one line that carries the parameter from the
node to the builder, and a parameter silently dropped there is the failure that
makes the escape hatch useless while looking fine. So the regression file's
fourth model carries `min_angle = 30` — a value chosen to select exactly what the
derived 18 does on a boss, every real crease there turning 90 and the cylinder's
seams 11.25. Regenerating the baselines confirmed it: the three PNGs came back
byte-identical and only the `.csg` moved, which is both the guard working and the
claim about the selection being checked.

## Does the preview rule constrain hand-written sugar?

No, and it was worth checking rather than assuming, since the point of the tool
nodes is that people build their own compositions out of them.

`$preview` is an ordinary special variable, so a user writes whatever rule they
want in one `if`. Verified with a module in a deliberately different shape —
inner only, no `difference` — which passes through under preview and builds under
render, entirely on its own terms:

```openscad
module my_fillet(r) {
    if ($preview) children(0);
    else union() { children(0); fillet_tool(r=r) children(); }
}
```

Three things make that work, and all three are deliberate. The four `*_tool`
nodes never pass through, so nothing built out of them inherits a rule its author
did not write. The passthrough lives in `fillet()` alone. And because `$preview`
is a config variable it can also be *passed* — `fillet(r=2, $preview=false)`
overrides per call, the same way `$fn` does, which fell out for free rather than
being designed.
