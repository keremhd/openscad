## What was built

### M0 — node scaffold (`3a17f2a10`)
- New `src/core/FilletNode.{h,cc}`: one node class + `FilletType` enum with four
  builtin modules — `fillet_tool`, `round_tool`, `chamfer_tool`, `bevel_tool`.
  Child 0 = target to analyse, children 1+ = selection brushes. Parses `r`/`t`
  (+ `min_angle`) and carries a `CurveDiscretizer` for `$fn/$fa/$fs`.
- The node is a **no-op returning empty geometry**. So `union(){ thing();
  fillet_tool() thing(); }` renders as just `thing()`.
- Wiring: `NodeVisitor.h` (visitable + default forward), `Builtins.cc`,
  `CMakeLists.txt`, and **both** evaluators:
  - `GeometryEvaluator::visit(FilletNode)` — the render path and the single
    place the real computation will grow.
  - `CSGTreeEvaluator::visit(FilletNode)` — the preview path; forces geometry
    evaluation through the same `GeometryEvaluator` and inserts the result as one
    CSG leaf.

### M1 — visual reference cases (`de6a7f494`)
- `fillet-visual-tests/`: operator-independent OpenSCAD scenes rendering the
  known-good result from classic idioms (annulus−torus, wedge−cylinder, …).
- Each case is a thin-slab cross section laying out base model / applied result /
  isolated tool, at a small and a large radius; junction cases use a contour
  stack of sections marching toward the meeting point.
- `_fillet_ref.scad` holds the shared reference tools and viewers; `render.sh`
  regenerates all PNGs into `png/` (gitignored).

### M6-prep — automated equivalence harness (`214b3dae1`)
- `fillet-equivalence-tests/`: checks operator output against the M1 reference
  **tessellation-independently**. Dilate each side by a small tolerance `t` and
  assert two-sided containment; the result is accepted when the leftover geometry
  is empty (an exact symmetric difference never is, because arc tessellations
  differ).
- `check_equivalence.sh` maps OpenSCAD's "Current top level object is empty."
  to a passing test. `run_all.sh` checks each case against its expected state.
- Ships a positive self-test (equal shapes at different `$fn` → PASS), a negative
  self-test (wrong radius → FAIL), and one real case (`fillet_tool` vs reference)
  that is **red until the geometry is implemented** and turns green automatically.

## Key decisions

- **No-op returns empty, not passthrough.** Semantically honest and matches the
  eventual preview behaviour.
- **Preview must equal render.** The first cut only wired the render evaluator, so
  preview fell back to unioning the node's children and showed the untouched
  child. Fixed by giving the preview evaluator its own `FilletNode` case that
  calls the same computation. Verified: `fillet_tool(r=2) cube(10)` previews blank,
  a plain cube still previews normally.
- **One computation, both paths.** Preview and render both call
  `GeometryEvaluator::visit(FilletNode)`; preview only wraps the result. The two
  paths cannot diverge.
- **Preview-skip belongs in the wrapper, not the node.** The node always computes
  the real tool (like `hull`/`minkowski`), so direct/tool-level use (intersection,
  inspection, equivalence files) stays correct. Skipping fillets in `$preview` for
  speed is an opt-in `if(!$preview)` in the future `fillet()` SCAD wrapper.
- **Equivalence testing is volume-with-tolerance, not exact-empty.** Exact
  symmetric difference leaves ~hundreds of stray facets from tessellation
  mismatch; the dilated two-sided containment collapses those to empty while a
  real defect survives.
